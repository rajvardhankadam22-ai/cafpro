1. Executive Summary & Document Control

CaféPulse is a real-time, multi-tenant inventory control and supply chain orchestration platform engineered specifically for specialty coffee roasteries, artisan espresso bars, and multi-location café franchises. The system bridges physical café floor operations (daily usage steppers, instant restocks, wastage logs) with public wholesale B2B supplier bidding, automated PO creation, price agreement contract mapping, and comprehensive audit accounting in Indian Rupees (₹).

1.1 Document Overview & Standards

This document serves as the formal Software Requirements Specification (SRS) compliant with IEEE Std 830-1998 and ISO/IEC/IEEE 29148:2018. It delineates all functional capabilities, non-functional performance benchmarks, data models, role-based security policies, and user acceptance criteria implemented across the system.

2. System Architecture & Database Design

CaféPulse operates on a serverless, event-driven architecture combining Next.js 15 App Router clients with Google Cloud Firestore for ACID-compliant real-time multi-document data synchronization.

2.3 Offline Fallback & Dual-Bus Synchronization Engine

To guarantee uninterrupted café point-of-sale and floor operations during internet connectivity dropouts, the system utilizes a Dual-Bus Synchronization Engine:

  • Client Event Bus: Emits local in-memory state updates instantly (0ms latency) to guarantee seamless, zero-lag UI feedback.
  • Local Storage Cache: Persists state snapshots scoped per userId under isolated keys (cafepulse_items_${uid}).
  • Firestore Real-Time Listener: Subscribes via onSnapshot using memoryLocalCache() to keep all multi-tab clients synchronized while completely eliminating lease-lock warnings.

3. Detailed Functional Requirements (FR)

3.1 Real-Time Stock Management & Inventory Catalog (FR-INV)

Req ID Feature Name Functional Description & Validation Rules
FR-INV-01 Live Stepper Adjustments Staff can increase (Restock) or decrease (Usage) stock directly from tables with single clicks. Atomic increments are applied to Firestore.
FR-INV-02 Automatic SKU Generation System automatically creates structured SKUs based on Category prefix, item name syllables, and pseudo-random numbers (e.g. COF-CHIK-428).
FR-INV-03 Dynamic Stock Status Items are dynamically classified as In Stock (Green), Low Stock (Amber, when ≤ Reorder Level), or Out of Stock (Red, when = 0).
FR-INV-04 CSV Export Engine Managers can export full or filtered catalog views to standard RFC 4180 CSV with formatted INR values and stock health tags.

3.2 Multi-Tenant Public Sourcing & B2B Vendor Proposals (FR-B2B)

Req ID Feature Name Functional Description & Validation Rules
FR-B2B-01 Real-Time Café Discovery Public supplier portal (/supplier/register) discovers all active registered cafés from Firestore users collection in real-time.
FR-B2B-02 Store-Specific Sourcing Demands Selecting a café dynamically loads that café's actual inventory items for wholesale rate card quoting.
FR-B2B-03 Custom Product Proposals Suppliers can pitch custom, unlisted ingredients via + Propose Custom Product with custom MOQ, SKU, unit, and wholesale rates.
FR-B2B-04 Targeted Proposal Inbox Proposals route directly to the designated café manager's inbox on /dashboard/vendors based on targetCafeId.
FR-B2B-05 1-Click Approval & Auto-Catalog Approving a proposal registers the vendor, updates price books, and auto-creates any proposed custom items into the store's inventory catalog.

3.3 Automated Shortage Radar & Purchase Orders (FR-ORD)

Req ID Feature Name Functional Description & Validation Rules
FR-ORD-01 Automated Shortage Radar Identifies items below safety thresholds and calculates optimal restock quantities: Suggested = PAR - CurrentQty.
FR-ORD-02 1-Click Bulk PO Generation Aggregates low-stock items grouped by supplier and auto-populates pre-filled Purchase Orders with contracted price agreements.
FR-ORD-03 Supplier Fulfillment & Dispatch Suppliers log in to /supplier/portal, inspect incoming PO line items, and mark orders as Dispatched with tracking numbers.
FR-ORD-04 Goods Receipt (GRN) Restock When physical goods arrive at the café, managers click Receive Goods to automatically increment catalog inventory counts.

4. Non-Functional & Security Requirements

4.1 Performance & Latency Benchmarks (NFR-PERF)

  • Client UI Response Time: Immediate local optimistic UI update within ≤ 16ms (60 FPS animation budget).
  • Cloud Firestore Latency: Remote document synchronization across active clients within ≤ 350ms under standard 4G/Broadband.
  • Cold Start & Static Page Load: First Contentful Paint (FCP) ≤ 0.8s across all static routes.

4.2 Role-Based Access Control (RBAC) Matrix (NFR-SEC)

☕ Head Barista Edit Items Restock & Waste Draft & Inspect Restricted No Access
🧑‍🍳 Shift Barista Read-Only Quick Usage (-1) No Access Hidden No Access
📋 Inventory Auditor Read-Only No Access Audit Trails Full Valuation No Access

4.3 Data Retention & Account Deletion (NFR-PRG)

Zero Data Retention Policy on Deletion: When an administrator triggers store deletion via /dashboard/team, all associated documents in users, inventory_items, categories, purchase_orders, supplier_applications, vendors, staff_members, and activity_logs are permanently purged via atomic multi-document deletes. The store is immediately unlisted from the public directory.
